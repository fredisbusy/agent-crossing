# 관계 탭 개선 요구사항

## 목표

- 선택 에이전트가 상대를 어떻게 인식하는지 근거와 함께 빠르게 이해하게 한다.
- 관계 정보와 상대의 실시간 상태를 시각적·의미적으로 분리한다.
- 계획, 이동 코드, 프롬프트형 진단 문자열이 관계 요약으로 노출되지 않게 한다.
- 비대칭 private perspective와 `not_modeled` 호감도 계약을 유지한다.

## 비목표

- 숫자형 호감도 모델이나 `RelationshipState` 업데이트 공식을 새로 정의하지 않는다.
- 반대 방향 에이전트의 기억으로 선택 에이전트의 관계를 보완하지 않는다.
- 관계를 추론하기 위해 공개 응답에 prompt, raw model response, embedding 또는
  private diagnostics를 추가하지 않는다.
- 관계 탭 개선을 명분으로 React/Vite/FastAPI 구조를 변경하지 않는다.

## 기능 요구사항

| ID    | 요구사항                                                         | 구현 완료 기준                                                                                      |
| ----- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| FR-01 | 관점의 주체를 페이지 제목에 명확히 표시한다.                     | `하은이 바라보는 관계`처럼 모든 요약의 주체가 한 번에 보인다.                                       |
| FR-02 | 관계 대상 목록과 선택한 관계 상세를 분리한다.                    | 목록 선택 시 상세만 바뀌며 전체 페이지가 다른 에이전트 화면으로 갑자기 이동하지 않는다.             |
| FR-03 | 관계 요약은 관계를 직접 설명하는 persona·memory 근거만 사용한다. | 계획, 이동 상태, 현재 위치, 프롬프트형 `키=값` 원문은 요약 후보에서 제외된다.                       |
| FR-04 | 명시적 관계 근거가 없으면 추측하지 않는다.                       | `아직 기록된 관계가 없습니다` 상태와 다음에 기록될 조건을 보여준다.                                 |
| FR-05 | 근거의 출처와 시점을 구분한다.                                   | `고정 성향`, `경험 기억`, `성찰`과 기록 시각을 한국어로 표시한다.                                   |
| FR-06 | 근거 수의 전체값과 잘림 여부를 구분한다.                         | 5개만 내려오면 `5개`로 단정하지 않고 전체값 또는 `5개 이상`을 표시한다.                             |
| FR-07 | 숫자형 호감도가 없음을 정확히 표현한다.                          | 기본 배지는 `정성 관계 기록`이며 숫자·게이지·긍정/부정 색상 점수를 만들지 않는다.                   |
| FR-08 | 상대의 실시간 상태는 별도 보조 영역에 둔다.                      | `상대의 지금`에서 행동, 실제 현재 위치, 목적지를 각각 정확한 레이블로 표시한다.                     |
| FR-09 | 반대 관점으로 전환할 수 있다.                                    | `수진의 관점에서 보기` 실행 시 선택 주체가 수진으로 바뀌고 수진의 private evidence만 다시 조회한다. |
| FR-10 | 오염된 문자열을 안전한 상태로 처리한다.                          | 내부 상태 코드 또는 진단형 문자열은 사용자 요약에 렌더링되지 않고 필터 상태로 기록된다.             |
| FR-11 | 모든 제품 문구를 한국어로 통일한다.                              | `TO`, `PERSONA`, `MEMORY`, `planning_route`가 기본 UI에 노출되지 않는다.                            |
| FR-12 | 관계 근거 조회 범위를 일반 기억 탭 표시 한도와 분리한다.         | 오래된 유효 관계 기억이 `memory_limit` 때문에 사라지지 않는다.                                      |
| FR-13 | 개요와 관계 탭의 역할을 분리한다.                                | 개요에는 축약된 관계 미리보기만 두고 전체 탐색·근거 확인은 관계 탭에서만 제공한다.                  |

## 비기능 요구사항

| ID     | 요구사항           | 기준                                                                                                           |
| ------ | ------------------ | -------------------------------------------------------------------------------------------------------------- |
| NFR-01 | 정확성             | 현재 위치와 목적지를 동일 필드로 표시하지 않는다.                                                              |
| NFR-02 | 개인정보·진단 경계 | prompt, raw response, model thought, decision trace를 관계 응답과 UI에서 제외한다.                             |
| NFR-03 | 접근성             | 키보드로 대상 선택·근거 열기·관점 전환이 가능하고 포커스가 보인다. 터치 대상은 최소 44×44px이다.               |
| NFR-04 | 가독성             | 본문 14px 이상, 보조 메타데이터 12px 이상을 기본으로 하며 색만으로 상태를 구분하지 않는다.                     |
| NFR-05 | 반응형             | 720px 이하에서는 대상 목록 다음에 상세를 한 열로 배치하고 가로 스크롤을 강제하지 않는다.                       |
| NFR-06 | 레이아웃 안정성    | 긴 근거는 상세 영역 내부에서 처리하며 한 항목 때문에 다른 대상 카드에 큰 빈 공간이 생기지 않는다.              |
| NFR-07 | 실제 데이터        | 빈 상태, 로딩, 오류를 명시하며 mock 관계나 fabricated metric으로 채우지 않는다.                                |
| NFR-08 | 계층 경계          | 관계 파생은 dashboard diagnostics/read-model 계층이 소유하고 Brain 결과 및 `/ws/world` 계약을 확장하지 않는다. |

## 핵심 수용 시나리오

1. **명시적 persona 관계**: 하은→지호는 하은의 persona 문장을 요약·근거로
   표시하고 지호→하은의 기억을 섞지 않는다.
2. **관계 없는 이동 관찰**: `정우가 planning_route 상태이다`만 존재하면 관계
   요약으로 쓰지 않고 `아직 기록된 관계가 없습니다`를 표시한다.
3. **진단형 기억**: `시간=... 에이전트=...` 형태 기억은 관계 상세와 공개 API에서
   제외하거나 안전한 관찰 문장으로 정규화한 뒤에만 사용한다.
4. **위치 정확성**: 이동 중인 상대는 `현재 위치`와 `목적지`가 서로 다른 값으로
   표시된다. 현재 위치를 계산할 수 없으면 `확인할 수 없음`으로 표시한다.
5. **근거 제한**: 전체 근거 12개 중 5개만 응답하면 `총 12개 · 최근 5개 표시`로
   나타난다.
6. **모바일**: 390px 폭에서 대상 선택, 요약, 근거, 관점 전환을 확대 없이
   읽고 조작할 수 있다.
7. **오래된 핵심 기억**: 일반 기억 탭이 최근 20개만 요청하더라도 그보다 오래된
   명시적 관계 기억이 관계 탭에서 누락되지 않는다.
